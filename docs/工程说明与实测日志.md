# mini_sentry_ws —— ROS 2 基础课程作业（4 题全做）

对应讲义《算法组 · ROS 2 基础》末尾的 4 道课后作业。讲义里只描述了 `mini_sentry` 这个 demo 的行为，
没有给源码，所以这里从零搭了一套**能直接 `colcon build` 的最小工程**，四道题分别落在不同节点上。

> **✅ 已在真机编译 + 跑通**：VMware 虚拟机 `Ubuntu 64 位 (2)`，
> Ubuntu 26.04.1 LTS + ROS 2 **Lyrical**（`/opt/ros/lyrical`），`colcon build` 两个包全部 Finished，
> 四道作业逐条验证通过（实测数据见 §3 每道题的"实测结果"）。
>
> 代码同时兼容 **Humble / Jazzy / Lyrical**（差异见 §5，用 `__has_include` 和版本无关的写法兜住了）。
> 如果你在自己机器上是 22.04 + Humble，把 `source /opt/ros/lyrical/setup.bash` 换成 `humble` 即可。

## 2. 编译与运行

```bash
# 1) 环境（每个新终端都要 source 一次）
source /opt/ros/lyrical/setup.bash      # 22.04+Humble 换成 humble；24.04 用 jazzy
export ROS_DOMAIN_ID=42                 # 防串车，同组同学约好同一个号

# 2) 编译
cd ~/mini_sentry_ws
sudo apt-get install -y python3-colcon-common-extensions   # 没装 colcon 才需要（别用 pip 装，会依赖冲突）
colcon build --parallel-workers 2       # 2 核机器建议限制并行，否则容易 OOM
source install/setup.bash               # 漏了这句会 "Package not found"

# 3) 一键起整套仿真（底盘、裁判、动作服务、决策、静态 TF、TF demo）
ros2 launch mini_sentry sentry.launch.py simulate_damage:=false match_duration:=120.0
```

> **Windows 上编译不了**：`colcon` / `ros2` 只在 Linux（或 WSL2 / 虚拟机）里有。
> 本工程没有 Windows 特定代码，放在 WSL 或 VMware 的 `~/` 下都能编译。

想边跑边看：

```bash
ros2 run rqt_graph rqt_graph
ros2 run rviz2 rviz2 -d src/mini_sentry/config/sentry.rviz   # Fixed Frame 是 odom
```

**实测编译耗时**（2 核 VM，`--parallel-workers 2`）：接口包 ≈ 1 分 25 秒，主包 ≈ 1 分 11 秒，
增量重编 ≈ 20–80 秒。

## 3. 四道作业分别怎么验收（含实测结果）

### 作业 1：`sentry_brain` 加"最后 60 秒回防"规则

**要求**：`stage_remain_time < 60` 时不再巡逻，回补给点待命。

**实现**（`src/mini_sentry/src/sentry_brain.cpp`）：

- 订阅 `/game_status`（自定义消息，练 Part 2.7）；
- 用 `rclcpp_action` 客户端异步发目标（`async_send_goal` + 回调，**不阻塞**，练 Part 2.9）；
- 每 100 ms 决策一次，优先级：**最后 60 s > 血量低 > 正常巡逻**；
- `defense_time` 是参数（默认 60），`supply_x/supply_y` 是补给点坐标（默认 0,0）；
- 回防时若巡逻目标还在跑，先 `async_cancel_all_goals()` 再改道；每个目标带序号，
  被取消的旧目标的回调不会再来改状态（否则会重复发目标、日志打两遍）；
- 时间/血量恢复正常后自动切回巡逻（方便反复演示）。

**验收步骤**：

```bash
# 终端 A：关掉掉血，只观察 60 s 规则
ros2 launch mini_sentry sentry.launch.py simulate_damage:=false match_duration:=120.0

# 终端 B：边跑边看状态
ros2 topic echo /game_status

# 终端 C：手动切模式
ros2 service call /set_mode mini_sentry_interfaces/srv/SetMode "{mode: 2}"   # 2=待命
```

**实测结果**（VM 内 `hw_launch.log`）：

- 启动后依次巡逻 `(1,1) → (4,1) → (4,3) → (1,3)`，每段 1.7–3.4 s 到达，`goto_server` 有反馈；
- 剩余时间降到 **58 s** 时打印
  `剩余 58 s < 60 s，进入回防：回补给点 (0.0, 0.0)`，取消巡逻目标，改道回 (0,0)，
  到点后打印 `已回到补给点，原地待命`；
- `ros2 service call /set_mode … {mode: 1}` → `success=True, message='已切换到 巡逻'`；
- `ros2 param set /referee_sim match_duration 70.0` 成功，随后 `stage_remain_time` 从 53 变 29
  （证明裁判仿真确实是每帧重读参数，不是只在构造里读一次）。

### 作业 2：`cmd_test` 速度改参数 + 参数回调 + `rqt_reconfigure`

**要求**：把写死的线速度/角速度变成参数，在线改能立刻生效，并用 `rqt_reconfigure` 拖动验证。

**实现**（`src/cmd_test.cpp`）：

- `linear_x`、`angular_z`、`max_speed` 三个参数；
- `add_on_set_parameters_callback` 里做范围校验：非法值直接 `successful=false` + `reason`，
  **参数不会被写进去**（这是和"只在构造里 declare 一次"的关键区别）；
- 10 Hz 把参数发到 `/cmd_vel`，底盘画圆（半径 ≈ `linear_x / angular_z`）。

**验收步骤**：

```bash
# 终端 A
ros2 run mini_sentry cmd_test
ros2 run mini_sentry chassis_sim        # 另开终端，让车真的动起来

# 终端 B：命令行调参
ros2 param get /cmd_test linear_x
ros2 param set /cmd_test linear_x 0.3
ros2 param set /cmd_test angular_z 2.0
ros2 param set /cmd_test linear_x 5.0   # 故意超限，应被拒绝且原值不变
ros2 topic echo --once /cmd_vel

# 终端 C：图形化拖滑条
ros2 run rqt_reconfigure rqt_reconfigure
```

**实测结果**（VM 内 `t2_*.txt`）：

| 动作 | `/cmd_vel` 实测 | 结论 |
|---|---|---|
| 启动默认 | `linear.x=0.6, angular.z=0.8` | 参数生效 |
| `param set linear_x 0.3` | `linear.x=0.3, angular.z=0.8` | 在线改立即生效 |
| `param set linear_x 5.0` | 返回 `Setting parameter failed: linear_x 超限，\|v\| 不能大于 max_speed=2.000000` | 非法值被回调拒绝 |
| 再 `param set angular_z 2.0` | `linear.x=0.3, angular.z=2.0` | 5.0 确实没写进去 |

### 作业 3：录 1 分钟 bag，回放看轨迹

**要求**：录 `/odom /tf /tf_static /game_status`，回放时在 RViz2 里看到轨迹，练 bag + `use_sim_time`。

**实现**：`scripts/record_demo.sh` / `scripts/replay_demo.sh`
（脚本会自动判断当前发行版的 `ros2 bag record` 是"话题直接跟在后面"的老语法，还是要 `--topics` 的新语法）。

```bash
# 终端 A：起仿真并让它跑起来
ros2 launch mini_sentry sentry.launch.py

# 终端 B：录 1 分钟（脚本内部是 timeout -s INT 60 + ros2 bag record）
bash scripts/record_demo.sh

# 看摘要
ros2 bag info bags/hw3_xxxxxx

# 终端 C：RViz2（Fixed Frame 设 odom，加 TF / Odometry 显示）
ros2 run rviz2 rviz2 -d src/mini_sentry/config/sentry.rviz

# 终端 D：带仿真时钟回放
bash scripts/replay_demo.sh bags/hw3_xxxxxx
# RViz2 里要开 use_sim_time：
#   ros2 param set /rviz2 use_sim_time true
```

**实测结果**（VM 内录了 40 s 的短版）：

- `ros2 bag info`：37.5 s / **1.9 MiB** / 3938 条 —— `/odom` 1871（≈50 Hz）、`/tf` 1878、
  `/game_status` 187、`/tf_static` 2；轻量话题录一分钟也就几 MB，不用怕磁盘；
- `ros2 bag play` 之后 `ros2 topic hz /odom` = **50 Hz**，`ros2 topic echo --once /odom` 有数据；
- 把 bag 里的 `/odom` 全取出来重画轨迹 → 得到完整矩形巡逻路线 `A(1,1) → B(4,1) → C(4,3) → D(1,3)`，
  说明轨迹数据完整、回放可复现。

> 讲义提醒：`/image` 这种大话题一分钟能到几十 GB，**录包别带图像**，除非只录几秒。

### 作业 4：订阅 `/image`、画框、发 `/image_debug`

**要求**：用 `cam2image` 发测试图，写节点订阅、画框、再发出来，用 `rqt_image_view` 看。

**实现**（`src/image_debug.cpp`）：

- 订阅 QoS 用 `rclcpp::SensorDataQoS().keep_last(1)`：BEST_EFFORT + 只留最新帧，
  和 `cam2image` 的发布端匹配（**订阅端 QoS 不能比发布端更严**，否则匹配不上）；
- `cv_bridge::toCvShare` 零拷贝取图，但要改像素，先 `clone()`，别污染原始 buffer；
- 画绿框 + 时间戳，用 `cv_bridge::CvImage` **保留原 header**（时间戳/frame_id 不能丢）再发。

**验收步骤**：

```bash
ros2 run image_tools cam2image --ros-args -p burger_mode:=true   # 终端 A
ros2 run mini_sentry image_debug                                 # 终端 B
ros2 run rqt_image_view rqt_image_view                           # 终端 C：选 /image_debug
```

**实测结果**（VM 内 `t4_*.txt` + 抓帧脚本）：

- `/image_debug` 输出 **30.3 Hz**、`sensor_msgs/msg/Image`、QoS `BEST_EFFORT / KEEP_LAST(1)`、`frame_id=camera_frame`；
- `ros2 param set /image_debug box_width 400` 成功（框宽在线可改）；
- 用另一个 BEST_EFFORT 订阅者抓一帧存 PNG：320×240 BGR8，图上有居中的绿框和 `frame <时间戳>` 文字
  —— 画框链路（`/image` → 处理 → `/image_debug`）真实成立。

## 5. 发行版差异（Lyrical 上必须改的三处）

这套代码第一次是在 **Lyrical** 上编译通过的，踩到的三个真实差异，已在代码里处理：

| 差异 | 现象 | 处理 |
|---|---|---|
| `ament_target_dependencies` 被移除 | CMake 报 `Unknown CMake command "ament_target_dependencies"` | 改成 `target_link_libraries(<可执行> PUBLIC rclcpp::rclcpp rclcpp_action::rclcpp_action …)`，接口包用 `mini_sentry_interfaces::mini_sentry_interfaces` |
| `cv_bridge/cv_bridge.h` 改名为 `.hpp` | `fatal error: cv_bridge/cv_bridge.h: No such file` | `#if __has_include("cv_bridge/cv_bridge.hpp")` 条件包含，Humble/Jazzy 走 `.h` |
| `tf2/LinearMath/Quaternion.h` 不存在 | 同上 | 不用 tf2 的数学库，直接 `q.z = sin(yaw/2); q.w = cos(yaw/2)` 构造四元数 |
| `tf2_ros` 头文件 `.h` 标弃用 | 一堆 deprecation warning | `__has_include` 优先用 `tf2_ros/buffer.hpp`、`transform_listener.hpp`、`transform_broadcaster.hpp` |
| rosbag2 录制语法变了 | `ros2 bag record -d 40 /odom …` 报 `unrecognized arguments: /odom` | 新版要 `--topics /odom /tf …`；`-d` 的含义也变成"单个文件最长时长"（会切片），**限时录制要用 `timeout -s INT 60 ros2 bag record …`** |
| rosbag2 默认存储改成 mcap | 想用 `.db3` / sqlite3 工具读会找不到文件 | 显式 `-s sqlite3`（`record_demo.sh` 里已写） |

另外 `cmake_minimum_required` 从 3.8 提到 3.10（CMake 4.x 会对 3.8 告警）。

## 6. 容易踩的坑（都已经在代码里处理）

1. **只 `declare_parameter` 不接回调** → `ros2 param set` 显示成功但节点行为不变。（`cmd_test`、`chassis_sim`、`referee_sim` 都处理了：referee 每帧 `get_parameter` 重读）
2. **`install(TARGETS ...)` 漏写** → `ros2 run` 报 `No executable found`。本工程 7 个 target 全部 install。
3. **launch/config/rviz 没 `install(DIRECTORY)`** → `sentry.launch.py` 找不到 `sentry.yaml`。已 install 两个目录。
4. **QoS 不匹配** → 订阅端写 `10`（RELIABLE）去订 BEST_EFFORT 的相机，会报
   `Last incompatible policy: RELIABILITY`。`image_debug` 用 `SensorDataQoS()`。
5. **在动作回调里 `.get()` 等待** → 死锁。`sentry_brain` 全程用回调，不 `spin_until_future_complete`。
6. **动作执行放在执行器线程里同步跑** → 其它回调饿死。`goto_server` 用 `MultiThreadedExecutor` + detached 线程。
7. **取消目标后又马上发新目标** → 旧目标的 result 回调晚一步回来，把 `goal_active=false`，
   于是 tick 重复发目标（表现是"已回到补给点"打印两次）。用目标序号过滤旧回调解决。
8. **TF 多发布者** → `odom→base_link` 只由 `chassis_sim` 发；`base_link→livox_frame` 只由 launch 的
   `static_transform_publisher` 发。别让两个节点同时发同一条边。
9. **回放 bag 忘 `--clock` / 忘 `use_sim_time`** → RViz2 里时间戳对不上，TF 报
   `extrapolation into the future`。`replay_demo.sh` 已带 `--clock --rate 2.0`，RViz2 还要开 `use_sim_time`。
10. **tf_demo 启动瞬间的 `target_frame does not exist`**：`chassis_sim` 的 TF 还没进 buffer，
    等 1–2 秒自然消失，不是错误。

## 7. 常见报错对照

| 报错 | 原因 | 处理 |
|---|---|---|
| `Unknown CMake command "ament_target_dependencies"` | 用了 Lyrical/新发行版 | 改 `target_link_libraries(… PUBLIC rclcpp::rclcpp …)` |
| `No executable found` | 没 install 或没 `source install/setup.bash` | 重新编译并 source |
| `package 'mini_sentry_interfaces' not found` | 只 source 了 `/opt/ros/...` | `source install/setup.bash` |
| `Last incompatible policy: RELIABILITY` | 订阅端 QoS 比发布端严 | 降到 `SensorDataQoS()` 或 BEST_EFFORT |
| `Lookup would require extrapolation into the future` | 用了比数据更新更晚的时间戳 | 查 TF 时传 `rclcpp::Time(0)` 或对齐时间源 |
| `"odom" passed to lookupTransform argument target_frame does not exist` | TF 还没发布 / frame_id 拼错 | 等 1–2 s；`ros2 run tf2_tools view_frames` |
| `cv_bridge` 转换失败 | 编码不是 BGR8（如 rgb8/mono8） | `toCvShare(msg, "bgr8")`，或按 `msg->encoding` 分支 |
| `ros2 bag record: unrecognized arguments: /odom` | 新版 rosbag2 不再接受位置话题 | 用 `--topics /odom /tf …` |
| `colcon build` 卡在 `cv_bridge` | 系统 OpenCV 与 ROS 版本冲突 | `rosdep install` 装 `cv-bridge`，别用 pip 版 opencv |

## 8. 下一步可以做什么（超出作业范围）

- `sentry_brain` 里把"回防"做成带滞回的迟滞逻辑（避免血量在阈值附近抖动）；
- `goto_server` 换成 PID / Pure Pursuit，并加 `nav2` 的 `FollowPath` 接口；
- `image_debug` 接 YOLO 装甲识别，把绿框换成检测结果（RoboMaster 视觉方向）；
- bag 回放时同步回放 `/game_status`，就能离线复盘一局的完整决策链。
